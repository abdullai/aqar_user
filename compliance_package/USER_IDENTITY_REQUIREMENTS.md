# متطلبات هوية المستخدم — User Identity Requirements

**اللغة المرجعية:** العربية أساساً؛ الإنجليزية للحقول التقنية فقط.

---

## 1) أنواع الحسابات في التطبيق الحالي

يُستنتج النوع من **`users_profiles.account_type`** ويُعرَّف في `AppRoleHelper` (`lib/core/workflow/app_role_helper.dart`):

- فرد / مالك فردي (`user`, `individual_seller`, `owner_individual`, …)
- مسوّق (`marketer`)
- مكتب / مؤسسة / شركة / وكالة (`office`, `institution`, `company`, `agency`)

**غير مُعرَّف كـ enum منفصل في التطبيق اليوم:**

- مدير نظام عام على مستوى المنتج (يوازيه `platform_staff` في DB)
- موظف دعم / مراقب امتثال / مشرف حكومي كأنواع حساب **مستقلة** — مذكورة في الطلب كمستقبل **نظام ويب إداري منفصل**؛ يُفضّل عدم تكرارها في تطبيق المستخدم النهائي.

---

## 2) الحد الأدنى للهوية اليوم

| المتطلب | المصدر الحالي |
|---------|----------------|
| معرف المستخدم | `auth.users` + `users_profiles.user_id` |
| رقم/هوية للتسجيل | `username` (غالباً 10 أرقام) أو مسارات `unified_national_number` حسب الترحيل |
| حالة التحقق | `verification_status` |
| فال للمسوّقين والمنشآت | `license_no`, `fal_license_expires_at`, `fal_compliance_hold`, `rega_fal_snapshot` (حسب تطبيق الهجرات على الإنتاج) |
| المنشأة | `org_units` + عضوية `org_memberships` + صلاحيات JSON |

---

## 3) المتطلبات الإضافية (ما بعد الربط الحكومي)

بعد توقيع واجهات **نفاذ / REGA / السجل التجاري / ناجز**:

1. تخزين **مصدر التحقق** و**وقت المزامنة** و**رمز الطلب** الرسمي (وليس فقط HTML أو mock).
2. فصل **الاسم القانوني** عن الاسم المعروض.
3. حقول انتهاء **الهوية/الإقامة** للأفراد عندما تفرضها الجهة.
4. سياسات احتفاظ (Retention) مرتبطة بعقد الجهة — **لا تُخزَّن في الكود**؛ تُعرَّف في سياسة تشغيل + هجرة تعليقات.
