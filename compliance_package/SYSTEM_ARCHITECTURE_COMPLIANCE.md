## 1) المكوّنات (الواقع المنفّذ + الوصف المعماري)

| المكوّن | الدور |
|---------|--------|
| **تطبيق جوال** | واجهة المستخدم الأساسية (Flutter) |
| **منصة ويب للمستخدمين** | واجهة إضافية (Flutter Web) |
| **نظام إداري ويب** | طبقة حوكمة داخلية — راجع `ADMIN_GOVERNANCE_MODEL.md` |
| **تطبيق سطح مكتب** | Flutter يدعم بناء desktop؛ لا يُفترض منتج «إداري سطح مكتب» منفصل في المستودع دون إثبات منفصل — يُعامل كـ **اختياري عند البناء** |
| **Backend** | Supabase (PostgREST + Auth + Storage + Realtime) |
| **طبقة الامتثال** | `regc_*` + RPCs |

## 2) تدفق البيانات (Data flow)

```text
[Mobile / Web Users] ──HTTPS JWT──► [Supabase API]
                                           │
                    ┌──────────────────────┼──────────────────────┐
                    ▼                      ▼                      ▼
              [PostgreSQL+RLS]      [Storage policies]    [Auth JWT]
```

---

## 3) طبقة الوساطة API

- جميع عمليات العميل عبر **API** (PostgREST / RPC).  
- **النظام الإداري:** لا وصول مباشر غير مُدار لقاعدة البيانات من واجهة المستخدم — نموذج حوكمة في `ADMIN_GOVERNANCE_MODEL.md`.

---

## 4) RBAC وRLS

- **RBAC:** أدوار قاعدة البيانات + صلاحيات التطبيق/الإدارة.  
- **RLS:** فرض على مستوى الصفوف — لا **bypass** من مسار التطبيق القياسي.

---

## 5) التدقيق الكامل (Full auditability)

- `regc_audit_logs` + `regc_security_events` + مسارات التطبيق الأخرى حسب التطور.
