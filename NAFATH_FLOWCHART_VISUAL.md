## المقارنة: نفاذ vs البريد/كلمة مرور

```
المسار          │ نفاذ              │ بريد + كلمة مرور
──────────────┼─────────────────┼──────────────────
الخطوات        │ 3                │ 2
الوقت          │ 3-5 ثواني        │ 2 ثانية
الأمان         │ عالي جداً        │ عالي (إذا قوية)
سهولة الاستخدام│ سهل جداً        │ متوسط
تذكر البيانات  │ نعم (الجهاز)     │ نعم (إذا اختار)
───────────────┴─────────────────┴──────────────────

✅ كلاهما متاح وفعّال
```

## حالات الأخطاء والمعالجة

```
┌─ خطأ: رقم هوية غير صحيح
│  └─ الرسالة: "أدخل 10 أرقام"
│  └─ الحل: أعد المحاولة
│
├─ خطأ: نفاذ غير مفعّل
│  └─ الرسالة: "الخدمة قيد الفعيل"
│  └─ الحل: استخدم البريد + كلمة مرور
│
├─ خطأ: المستخدم رفض في نفاذ
│  └─ الرسالة: "تم الرفض"
│  └─ الحل: حاول مرة أخرى
│
├─ خطأ: انتهاء المهلة الزمنية
│  └─ الرسالة: "انتهت المهلة"
│  └─ الحل: ابدأ طلب جديد
│
└─ خطأ: خطأ الشبكة
   └─ الرسالة: "تعذر الاتصال"
   └─ الحل: تحقق من الإنترنت
```

## الأمان: أين تذهب البيانات؟

```
المستخدم (الهاتف/الويب)
    │
    │ لا ترسل أبداً:
    ├─ مفاتيح نفاذ API ❌
    ├─ secret/app key ❌
    └─ بيانات حساسة ❌
    │
    └─ ترسل فقط:
       ├─ رقم الهوية ✅
       └─ access token (من Supabase) ✅
              │
              ↓
         Edge Function (الخادم)
              │
              ├─ هنا الأمان:
              ├─ مفاتيح نفاذ في env ✅
              ├─ بدون expose للعميل ✅
              ├─ RLS policies ✅
              └─ CORS محمي ✅
              │
              ↓
         قاعدة البيانات (Supabase)
              │
              └─ جميع البيانات محفوظة
                 بشكل آمن ✅
```
