# التكامل مع الجهات الحكومية (نفاذ — REGA — فال)

هذا المستند يشرح **ما هو مطبّق في الكود** و**كيف تكمل التكامل الحقيقي** بعد الحصول على التراخيص والعقود الرسمية.

## مبدأ أمني (إلزامي)

| القاعدة | السبب |
|--------|--------|
| **لا تضع مفاتيح API أو أسرار جهات حكومية داخل تطبيق الجوال أو الويب العام** | يمكن استخراجها من الحزمة؛ المخالفة تتعارض مع سياسات الجهات ومتاجر التطبيقات. |
| **الأسرار على الخادم فقط** (Supabase Edge Functions + Secrets، أو خادمكم الخاص) | التطبيق يستدعي دوال موثّقة بمفتاح `anon` فقط؛ الخادم يحمل الاعتماد الحقيقي. |
| **تدقيق عقود** نفاذ / الهيئة قبل الإنتاج | واجهات وشروط الاستخدام تتغير؛ الاعتماد يكون باسم منشأة مسجّلة. |

## بوابات ما بعد الدخول (موجودة — ليست جديدة)

بعد تسجيل الدخول واجتياز OTP، يُلفّ التطبيق لوحة التحكم بـ **`PostAuthShell`** (`lib/screens/post_auth_shell.dart`).  
الترتيب مُعرَّف في **`PostAuthGatePipeline`** (`lib/core/workflow/post_auth_gate_pipeline.dart`) ويشمل مثلاً:

- قبول الشروط القانونية عند تغيّر النسخة  
- تغيير كلمة المرور الإلزامي  
- حد الأجهزة الموثوقة  
- انضمام مؤسسة بانتظار موافقة  
- إكمال الرقم الوطني الموحّد للمسوّقين  
- الاعتراف بمراجعة بيانات الملف (`profile_data_revision`)  
- **فال منتهية أو تجميد امتثال** → شاشة تجديد  
- **توقيع مفقود** → شاشة التوقيع  
- تحذير إن بقي على انتهاء فال أقل من 7 أيام  

عند **إعادة فتح التطبيق من الخلفية** يُستدعى تحديث صامت لإعادة تقييم نفس الشروط (دون إعادة تسجيل الجهاز من الصفر).

**إصلاح مهم:** إذا كان `users_profiles` غير موجود أو فشل الاستعلام فكان `complianceRow == null`، كانت دوال مثل `needsSignature` تُرجع `false` فيتخطى المستخدم **كل** بوابات التوقيع/فال دون تنبيه. الآن: غياب الصف بعد تجهيز الجهاز يوجّه إلى خطوة **`profileRecordMissing`** (شاشة إعادة المحاولة/تسجيل الخروج)، وتم تحسين `loadProfileRow` بمحاولة ثانية بأعمدة أقل عند أخطاء الاستعلام. أثناء التشغيل الطبيعي يعمل **مراقب دوري (~75 ثانية)** يعيد الفحص مع التحديث الصامت عند العودة للواجهة.

## ما هو جاهز في المشروع

### 1) التحقق من رخصة فال (FAL) — REGA

- **العميل:** `lib/services/fal_license_service.dart` يستدعي Edge Function باسم `verify_fal_license`.
- **الخادم:** `supabase/functions/verify_fal_license/index.ts` يجلب صفحة التفاصيل العامة من بوابة الهيئة ويستخرج حقولاً (تقريبية) أو يستخدم بيانات اختبار معروفة للتطوير.
- **الاستخدام:** شاشة إضافة عقار (`add_property_page`) تستدعي التحقق عند إدخال رقم الرخصة.

### 2) ربط ترخيص الإعلان العقاري (رقم الإعلان — Elan)

- **الاستيراد من بوابة الهيئة:** `lib/screens/rega_ad_license_import_page.dart` (WebView + استخراج نص / `__NEXT_DATA__`).
- **بعد الربط من لوحة «إعلاناتي»:** عند وجود **رقم رخصة فال** مستخرج من البيانات، يُستدعى **نفس** `verify_fal_license` تلقائياً ويُخزَّن ملخص في `fal_license_verify` داخل الحمولة المرسلة للخادم.

### 3) نفاذ الوطني الموحّد (Nafath)

- **العميل:** `lib/services/nafath_auth_service.dart` + زر **«الدخول عبر نفاذ»** في `lib/screens/login_screen.dart`.
- **الخادم:** `supabase/functions/nafath_session/index.ts` — حالياً يعيد `not_configured` حتى تفعّل التكامل وتضيف المنطق حسب عقدكم.
- **التفعيل لاحقاً:** ضبط Secret باسم `NAFATH_INTEGRATION_ENABLED=true` ثم تنفيذ مسار المصادقة الرسمي داخل الدالة (OAuth / REST حسب الوثائق التي تزوّدكم بها الجهة).

## خطوات النشر بعد الحصول على التراخيص

1. نشر/تحديث Edge Functions:  
   `supabase functions deploy verify_fal_license`  
   `supabase functions deploy nafath_session`
2. إضافة الأسرار من لوحة Supabase → **Edge Functions → Secrets** (وليس في `pubspec` أو `.env` المرفوع لـ git).
3. اختبار من تطبيق مبني بـ `--dart-define` لمفتاح Supabase فقط.

## ملاحظة قانونية

الاعتماد على **كشط HTML** من مواقع حكومية قد يتعارض مع شروط الاستخدام؛ الحل الدائم هو **واجهة برمجية رسمية** بعد التعاقد. الكود الحالي يوفّر مساراً عملياً للتطوير ويمكن استبداله باستدعاء API رسمي داخل نفس Edge Function دون تغيير واجهة التطبيق.
