# تسليم نظام عقار — مواصفات الربط مع قاعدة البيانات والمنتج

هذا الملف يحدد **ما نحتاجه منك** (SQL / سياسات / بيانات) و**ما يفترض أن يفعله التطبيق** حتى يكون النظام متكاملاً.

---

## 1) مساران لإضافة إعلان (مهم)

| المسار | متى؟ | ما يُنشأ في DB | يظهر في «إعلاناتي» |
|--------|------|----------------|---------------------|
| **مستخدم موثّق** (`account_profiles.verified = true`) | إضافة عقار مباشرة | صف في `properties` + `property_images` | تبويبات حسب `properties.status` |
| **مستخدم غير موثّق** | نفس نموذج الإضافة | صف في `listing_requests` فقط (بدون `properties`) | **قائمة طلبات** داخل تبويبات المعلن + صفحة **حالة الطلب** |

إن لم تُعرض طلبات `listing_requests` في الواجهة، يبدو للمستخدم أن «الإعلان اختفى».

---

## 2) ما نحتاجه من قاعدة البيانات (قائمة تحقق)

1. **`listing_requests`**
   - أعمدة: `id`, `owner_id`, `title`, `city`, `status`, `preview_property_id` (إن وُجد), `payload_json` أو ما يعادله.
   - **RLS**: المالك يقرأ/يحدّث صفوفه؛ (اختياري) مسوّق يقرأ طلبات **مفتوحة** أو المدعو فقط.

2. **`properties`**
   - `status` متوافق مع `lib/core/workflow/listing_workflow.dart` (مثل `waiting_mediator`, `contract`, `published`…).
   - **RLS للمسوّق**: سياسة قراءة العقار المرتبط بدعوته — انظر `supabase/sql/20260328_marketer_preview_property_rls.sql`.

3. **`property_images`**
   - ربط `property_id` + `path`؛ سياسة قراءة للمسوّق لنفس العقارات المسموح بها أعلاه.

4. **`listing_request_invites`**
   - لظهور الدعوات عند المسوّق؛ إنشاء دعوات عند فتح الطلب للتسويق (منطق أعمال أو تريغر).

5. **`users_profiles`**
   - صف لكل `auth.users.id` بعد التسجيل (تريغر أو Edge Function) حتى تظهر **الإعدادات** بشكل صحيح.

6. **`account_profiles`** (إن وُجد)
   - `account_type`, `verified` متزامنان مع `users_profiles` لتفادي اختلاف السلوك.

---

## 3) سلوك الشريط السفلي (حسب نوع الحساب)

| النوع | زر الوسط |
|--------|----------|
| فرد / مالك / `user` | **إضافة إعلان** → `AddPropertyPage` |
| مسوّق / مكتب / مؤسسة / شركة | **طلب تسويق** → `CreateListingRequestPage` |

«إعلاناتي» للمسوّق = تبويبات الدعوات/العروض/العقود/التصاريح/المنشور.

---

## 4) ما تريده لاحقاً (رئيسية منفصلة للمسوّق)

يتطلب تصميم واجهة: **IndexedStack** مختلف لـ `home` حسب `_isMarketingAccountType` (لوحة أعمال، إحصائيات، روابط للفريق). غير منفّذ في هذا التسليم؛ يُضاف كمرحلة منفصلة.

---

## 5) ملفات SQL مرفقة في المشروع

- `20260328_marketer_preview_property_rls.sql` — رؤية المسوّق للعقار/الصور المرتبطة بالدعوة.
- تنفيذ أي migration ناقص لأعمدة `properties` / `listing_requests` حسب المخطط الفعلي لديك.

---

## 6) اختبار قبول سريع

1. حساب **غير موثّق** → إضافة إعلان → يظهر **طلب** في تبويب «بانتظار التسويق» ويفتح **حالة الطلب**.
2. حساب **موثّق** → إضافة عقار → يظهر في **نفس التبويب** كعقار بحسب `status`.
3. مسوّق مدعو → يرى **صورة المعاينة** بعد تطبيق سياسات RLS.
4. الإعدادات تعرض `account_type` والهاتف إن وُجد الصف في `users_profiles`.
