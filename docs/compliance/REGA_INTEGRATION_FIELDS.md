# تكامل الهيئة العامة للعقار (REGA) — متطلبات الحقول لكل فئة حساب

> هذه الوثيقة تلخّص متطلبات الهيئة العامة للعقار في المملكة العربية السعودية
> (Real Estate General Authority — REGA) لتسجيل المستفيدين على المنصّات
> الإلكترونية المرخّصة، وتوضّح الحقول المطلوبة لكل فئة حساب داخل التطبيق،
> ومسار الربط التقني المستقبلي.

## 1) خلفية تنظيمية

- **رخصة فال (FAL)** هي الترخيص الرسمي الذي تصدره الهيئة العامة للعقار للأفراد
  والمنشآت لمزاولة الوساطة العقارية والتسويق العقاري.
- منذ تطبيق نظام الوساطة العقارية، رخّصت الهيئة العامة للعقار أكثر من **71
  منصّة إلكترونية** بترخيص فال بعد استكمال **التكامل التقني** مع الهيئة.
- مرجع الخدمة الرسمي:
  - <https://rega.gov.sa/en/eservices/fal-real-estate-brokerage/>
  - <https://aqari.rega.gov.sa/> (الواجهة الإلكترونية)

> **ملاحظة مهمة**: حتى تاريخ هذه الوثيقة، لا تنشر الهيئة مواصفة OpenAPI/Swagger
> عامّة. التكامل التقني يتم عبر **اتفاقية ثنائية** مع الهيئة بعد الترخيص. لذلك
> يجب أن يكون التطبيق جاهزاً بـ:
> 1) **مفاتيح Edge Functions جاهزة** (`verify_fal_license`، `verify_unified_cr`)
> 2) **شكل بيانات موحّد** على جانب التطبيق لتسهيل الربط لاحقاً.

## 2) الفئات داخل التطبيق وترتيبها

ترتيب الفئات داخل شاشة `account_type_setup_screen.dart` (مطابق لطلب المستخدم):

| الترتيب | المفتاح الداخلي    | الفئة                  | يحتاج توثيق REGA؟ |
|---------|---------------------|------------------------|-------------------|
| 1       | `individual_seller` | فرد / مالك             | ❌ — هوية فقط     |
| 2       | (لا يوجد نوع)       | عضو ضمن فريق           | ❌ — انضمام لمنشأة|
| 3       | `marketer`          | مسوّق عقاري فردي       | ✅ — فال          |
| 4       | `office`            | مكتب عقاري             | ✅ — فال + سجل تجاري |
| 5       | `institution`       | مؤسسة عقارية           | ✅ — فال + سجل تجاري |
| 6       | `company`           | شركة عقارية            | ✅ — فال + سجل تجاري |
| (هامش)  | `user`              | مستخدم (تصفّح فقط)     | ❌                |

## 3) الحقول المطلوبة لكل فئة

### 3.1) فرد / مالك (`individual_seller`)

| الحقل                       | إلزامي | المصدر          |
|------------------------------|--------|------------------|
| الاسم الأول                  | نعم    | إدخال يدوي / نفاذ |
| الاسم الثاني                 | نعم    | إدخال يدوي / نفاذ |
| الاسم الثالث                 | اختياري | إدخال يدوي       |
| الاسم الرابع (العائلة)       | نعم    | إدخال يدوي / نفاذ |
| رقم الهوية الوطنية (10 أرقام) | نعم   | إدخال يدوي / نفاذ |
| رقم الجوال (05XXXXXXXX)      | نعم    | إدخال يدوي       |
| البريد الإلكتروني             | نعم    | إدخال يدوي       |
| كلمة المرور                  | نعم    | إدخال يدوي       |
| التوقيع الإلكتروني           | نعم    | لوحة توقيع       |

### 3.2) عضو ضمن فريق (Team member)

> لا يوجد توثيق REGA مستقل للعضو — صلاحياته تأتي من **منشأته الأم**
> (المكتب/المؤسسة/الشركة). المنشأة هي صاحبة رخصة فال.

| الحقل                       | إلزامي | المصدر                    |
|------------------------------|--------|----------------------------|
| رقم الهوية الوطنية           | نعم    | إدخال يدوي                 |
| رقم الجوال                   | نعم    | إدخال يدوي                 |
| الاسم الرباعي                | نعم    | إدخال يدوي / نفاذ          |
| البريد الإلكتروني             | نعم    | إدخال يدوي                 |
| رمز/QR انضمام للمنشأة         | نعم    | يُولّده مدير المنشأة       |
| كلمة المرور + التوقيع          | نعم    |                             |

### 3.3) مسوّق عقاري فردي (`marketer`)

| الحقل                         | إلزامي | المصدر                          |
|--------------------------------|--------|----------------------------------|
| **رقم رخصة فال (10 أرقام)**    | نعم    | `verify_fal_license`             |
| اسم المسوّق (كما في فال)        | يُجلب  | استجابة فال                      |
| تاريخ بداية ونهاية الرخصة      | يُجلب  | استجابة فال                      |
| حالة الرخصة (سارية/منتهية)     | يُجلب  | استجابة فال                      |
| رقم الهوية الوطنية             | نعم    | إدخال يدوي (يُطابق فال)          |
| الرقم الموحّد (للأفراد)        | اختياري | إدخال يدوي                       |
| رقم الجوال                     | يُجلب/إدخال | استجابة فال أو يدوي            |
| البريد الإلكتروني               | يُجلب/إدخال | استجابة فال أو يدوي            |
| المدينة / الحي / المنطقة       | يُجلب  | استجابة فال                      |
| كلمة المرور + التوقيع          | نعم    |                                  |

### 3.4) مكتب / مؤسسة / شركة عقارية (`office` / `institution` / `company`)

نفس حقول المسوّق + الإلزامات التالية:

| الحقل                                     | إلزامي | المصدر                          |
|---------------------------------------------|--------|----------------------------------|
| **رقم رخصة فال للمنشأة**                    | نعم    | `verify_fal_license`             |
| **الرقم الموحّد للسجل التجاري (10 أرقام)**   | نعم    | `verify_unified_cr` (وزارة التجارة) |
| الاسم الرسمي للمنشأة (كما في السجل)         | يُجلب  | استجابة وزارة التجارة            |
| رقم السجل التجاري وتاريخ الإصدار            | يُجلب  | استجابة وزارة التجارة            |
| النشاط الرئيسي                              | يُجلب  | استجابة وزارة التجارة            |
| رأس المال                                   | يُجلب  | استجابة وزارة التجارة            |
| حالة السجل (ساري/مشطوب)                     | يُجلب  | استجابة وزارة التجارة            |
| الهوية الوطنية للمالك/المدير المخوّل         | نعم    | إدخال يدوي                       |

> ⚠️ لا يُسمح بإكمال تسجيل المنشأة إذا كان السجل التجاري **غير ساري** (مشطوب
> أو في حالة تصفية).

## 4) تكامل الـ Edge Functions الحالي

### 4.1) `verify_fal_license` — استعلام رخصة فال

- **المدخل**: `{"license_no": "1234567890"}`
- **المخرج** (نموذج):
  ```json
  {
    "valid": true,
    "status": "active",
    "broker_name": "محمد بن عبدالله الفلاني",
    "broker_national_id": "1234567890",
    "broker_email": "broker@example.com",
    "broker_mobile": "+966501234567",
    "city": "الرياض",
    "district": "العليا",
    "region": "منطقة الرياض",
    "license_type": "مسوّق عقاري فردي",
    "license_no": "1234567890",
    "license_status_text": "سارية",
    "start_date": "2025-01-15",
    "end_date": "2026-01-14",
    "source": "rega"
  }
  ```
- **حالات الفشل**:
  - `invalid_license_no` — الرقم ليس 10 أرقام
  - `not_found` — غير موجود في سجلات الهيئة
  - `expired` — منتهي الصلاحية
  - `network_error` — تعذّر الاتصال (يُعرض زر WebView احتياطي)

### 4.2) `verify_unified_cr` — استعلام السجل التجاري الموحّد

- **المدخل**: `{"unified_cr_no": "1234567890"}`
- **المخرج** (نموذج):
  ```json
  {
    "ok": true,
    "valid_for_active": true,
    "entity_name_ar": "شركة الفلاني العقارية للوساطة",
    "registry_status_ar": "سارية",
    "commercial_reg_no": "1010234567",
    "issue_date": "2020-05-10",
    "activity_ar": "وساطة عقارية",
    "capital": 500000,
    "source": "moc"
  }
  ```

## 5) بيئة التجربة (Sandbox)

> الهيئة لا توفّر حالياً **sandbox عام مفتوح** للتكامل. الخيارات المتاحة:

1. **بيئة المنصّة الداخلية** (مرحلة التطوير):
   - يستجيب `verify_fal_license` ببيانات وهمية إذا كان الرقم يبدأ بـ `99` —
     يُسمح لها بتجاوز فحص النشاط فقط في وضع التطوير
     (`AppConfig.allowDevTestSubscriptionGrant = true`).
2. **مرحلة الترخيص الرسمي**:
   - بعد الحصول على شهادة فال للمنصّة، تُمنح بيئة UAT خاصّة عبر **رابط
     ثنائي مغلق** من فريق التكامل التقني في REGA.
3. **WebView Fallback**:
   - عند تعذُّر الاتصال بـ Edge Function، يُتاح زر فتح صفحة الهيئة الرسمية
     داخل WebView لتأكيد البيانات يدوياً ثم نسخها إلى التطبيق
     (`FalLicenseWebVerifyPage`).

## 6) خطوات الربط المستقبلية

1. الحصول على ترخيص فال للمنصّة من الهيئة العامة للعقار.
2. إكمال **اتفاقية التكامل التقني** (Technical Integration Agreement).
3. استلام مفاتيح UAT + بيانات الاعتماد للوسيط/الـ Broker الخاص بالهيئة.
4. تعديل Edge Functions على Supabase (`verify_fal_license`،
   `verify_unified_cr`) لاستخدام نقاط النهاية الرسمية بدل الـ stub الحالي.
5. إضافة Webhooks لاستقبال تحديثات حالة الرخصة فور تغيُّرها (انتهاء، إيقاف،
   تجديد) — يحدّث `subscription_billing_context` فوراً عبر Realtime.
